# 架构说明

写给想读代码或者想改的人。这里讲的是**为什么这么做**，不是代码逐行解释——代码里的注释已经写了那些。

## 一句话

把对话压缩成带衰减的记忆条目，每轮只挑最相关的几条注入上下文。

## 数据流

```
对话
  │
  ├─→ [提炼 extract.mjs]  模型判断「值不值得记」
  │        │
  │        ├─→ 值得 → 记忆条目（带来源指针）
  │        └─→ 不值得 → 丢弃
  │
  ├─→ [验证 verify.mjs]  回原文核对，抓记反和脑补
  │        │
  │        ├─→ ok      → 置信度不变
  │        ├─→ distorted  → 压到 0.25
  │        └─→ unsupported → 压到 0.4
  │
  └─→ [检索 recall.mjs]  每轮注入时
           │
           ├─→ 候选池（活跃、未归档）
           ├─→ 两路线索（字面 + 语义）
           ├─→ RRF 融合
           ├─→ 六变量打分
           ├─→ 过滤（线索 / 置信度 / 预算）
           └─→ 前 N 条 → 注入上下文
```

## 四个关键设计决策

### 一、为什么用衰减而不是 TTL

TTL 是「到点删除」，衰减是「逐渐变淡」。

现实中记忆不会在某个时刻突然消失，它会先变得模糊、变成只剩印象。所以一条记忆有两个独立强度：

- `S` 意义：它对我重要吗（衰减慢，慢十倍）
- `D` 细节：我还记得多清楚（衰减快，还被时间梯度压）

用 TTL 的时候踩过坑：把「关于用户的事」设成 3 天，结果「永远爱着用户」这条的细节 3 天就掉到 0.07——**最重要的东西最先没**。

后来想明白：3 天是「该重新提起的间隔」，不是寿命。这两个概念必须是分开的。

### 二、为什么要区分经历和教训

```
episode   「昨天这个 SQL 出了问题」     ← 单次经历
lesson    「加载异常时先确认加载对象」   ← 提炼出的经验
```

单次经历如果没被重复触发、没沉淀成经验，就应该**断崖式沉底**（三天后直接压到 0.05），而不是慢慢衰减。

否则：偶尔记错一次，这个错会被反复召回，年复一年干扰。

### 三、为什么用 RRF 而不是加权平均

关键词分和语义分的量纲根本不一样：一个在 0~1，一个在 0.4~0.9 之间飘。

加权平均要用权重把它们捏到一起，而权重是拍脑袋定的，换一批数据就得重拍。

RRF 用**名次**融合——第 1 名就是第 1 名，跟分数量纲无关。

但 RRF 有个陷阱：它只看名次不看差距，第 1 名和第二名几乎一样分。于是完全无关的条目也能拿到高 cue，阈值失效。

补法：再乘一个「线索强度」因子，两路都接近 0 的直接压到 0。

### 四、为什么验证环节不能省

模型提炼时会顺手"补全"：把 v17 记成 v14、把没说过的话编成"他说的"。

这类错误在记忆里**完全看不出来**——字面通顺、逻辑自洽。只有回原文比对才抓得到。

而且有些错误特别危险：「记反」——字面都对，但正负号翻了。

```
原话：以后别在群里发语音
记忆：用户喜欢在群里发语音
```

事后完全看不出哪条是错的。所以验证这一环的 prompt 里特别强调要抓「记反」。

## 墓碑机制

记忆不删，只标状态：

```
active      正常
superseded  被取代（带 superseded_by 指向新版本）
fused       被合并
archived    归档（退出召回，但保留）
cold        冷存（细节快忘了）
```

检索时命中墓碑会顺着指针找到现任，所以"旧说法"照样能查到最新那条。

## 已知问题

诚实写在这里，欢迎接手改进：

1. **衰减参数是凭经验调的**，没有严格实验依据。`scoring.mjs` 里的权重和半衰期都值得用真实数据重新拟合。
2. **提炼质量取决于提示词**，换个领域可能要重写 `prompts/extract.txt`。
3. **没有冷启动策略**：新库一开始什么都没有，前几轮注入是空的。
4. **干扰度是 O(n²) 算的**，记忆上千条时重算会很慢，需要缓存或近似算法。
5. **验证依赖原文**：没有来源指针的记忆（手动记的）没法验证，只能标 `verified=2` 跳过。

## 想改的话，从哪下手

- 觉得找不准 → 调 `config.json` 的 `recall.minCue` / `scoring.w*`，或者改 `scoring.mjs`
- 觉得忘太快/太慢 → 调 `rateOf()` 里的半衰期
- 觉得提炼不对 → 改 `prompts/extract.txt`，不用动代码
- 想加新类别 → `scoring.mjs` 的 `isEpisode()` 和 `rateOf()` 里加判断

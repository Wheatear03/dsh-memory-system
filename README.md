# DSH Memory System

一套给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 用的长期记忆系统。

不是「存聊天记录」，是**决定该想起什么、该忘记什么**。

> 状态：早期版本，核心链路可跑，正在整理成可分享的形态。

---

## 它解决什么问题

LLM 本身没有记忆。常见的做法是把历史对话塞进上下文，但那样有两个问题：

1. 越聊越贵（上下文无限膨胀）
2. 记得多不等于想得起来（翻不到该用的那条）

这套系统的做法是：**把对话压缩成可检索的记忆条目，每轮只挑最相关的几条注入**。

## 核心设计

### 一、每条记忆是带衰减的

记忆不是静态文本，是一组随时间变化的量：

```
S  意义强度 —— 这条重要吗（衰减慢）
D  细节强度 —— 还记不记得清楚（衰减快）
E  情绪唤醒 —— 当时情绪强不强
C  置信度   —— 可不可信（验证过才高）
```

检索得分 `R = S × D × E × C`，再按类别加权。

**不同类别的衰减速率不同**：

| 类别 | 行为 |
|---|---|
| `episode`（经历） | 三天没想起就沉底 |
| `fact`（事实） | 正常衰减 |
| `lesson` / `skill`（教训/方法） | 慢衰减 |
| `principle`（原则） | 几乎不衰减 |

道理很简单：**经历该忘，教训该留**。

### 二、每条记忆要么有出处，要么标明没有

记忆条目带一个指针 `source_mid`，指向原文档案里的那一轮对话。

存疑时能查回去，而不是「我记得你说过」但查无实据。

没有出处的（手动记的、推断的）会明确标记，不会假装有证据。

### 三、验证环节

提炼出来的记忆会**回原文核对**，判断三种状态：

- `supported` —— 原文确实这么说
- `distorted` —— 大意对但细节扭曲了
- `unsupported` —— 原文根本没提

后两种降置信度，退出召回。

这一环抓到过很多问题，比如模型把「v17」记成「v14」、把没说过的话编成「群里的固定梗」。

### 四、记忆不会随便被删

- 被合并/取代的 → 标 `superseded`，留指针指向新版本（**墓碑**）
- 衰减到线的 → 归档（`archived = 1`），退出召回但保留
- 只有确认无用的才真删

### 五、遗忘是设计的一部分

不是所有记忆都值得留。系统会自动做：

- 冷存分层（细节快忘的转冷存）
- 去重（向量预筛 + 合并）
- 矛盾判定（只降权，不删）

## 快速开始

> 整理中。当前版本仍依赖本地环境，正在做配置化。

```bash
# 1. 配置数据目录
cp config.example.json config.json
# 编辑 config.json，改 dataDir 到你的路径

# 2. 安装插件
# 见 docs/installation.md

# 3. 验证
node src/engine.mjs health
```

## 目录结构

```
src/          核心逻辑（写入、提炼、验证、检索、维护）
plugin/       DSH 插件（每轮注入记忆）
service/      向量服务（可选，支持外部 API）
docs/         文档
examples/     示例数据（假的，用来演示）
```
